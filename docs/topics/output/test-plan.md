# Output — test plan

Evidence lives in `test/cli.test.ts`, which runs the CLI as a subprocess against this repository
and validates every line of every stream against the schema for its exact `(id, version)` pair:
the protocol schemas shipped by `@flyingrobots/parley-emit`, `schemas/footprint.composition.schema.json`,
`schemas/footprint.landing.schema.json`, `schemas/footprint.blast_radius.schema.json` (1.1.0) and
`schemas/footprint.overlap.schema.json`. The landing plan's derivation is pure, so its evidence
is in `test/landing.test.ts`, over the fixture repositories under `test/fixtures/landing/` — each a
directory holding the documents footprint reads and a `changed-files.txt` standing in for the diff,
so the suite needs neither git nor the network. `test/exports.test.ts` holds the export-surface
cases, which are a pure function over graft's JSON and run without graft: its fixtures under
`test/fixtures/` were captured from real `graft struct exports --json` runs on this repository.
`test/languages.test.ts` holds the unanalysed-language cases, over the fixture changed-file lists
under `test/fixtures/languages/`, in the same `changed-files.txt` convention as the landing
fixtures: a pure function over paths, needing neither git nor graft. The computation behind the
fourth result lives in `test/overlap.test.ts`, over `{number, title, isDraft, files}` records and
over the text `gh` writes when it fails, so no test needs the network or an open pull request on
this repository. `test/languages-drift.test.ts` holds the drift case against the *installed*
graft (flyingrobots/footprint#21): it reads `src/languages.ts`'s extension list from source and
the installed `@flyingrobots/graft`'s own `dist/parser/lang.js` from disk, so it needs graft
installed and fails loudly, naming the path, rather than skipping, if either is missing.

`test/systems.test.ts` holds the grouping cases (flyingrobots/footprint#11). The system of a call
site and the mitigation of a row are pure functions over paths, so every case but one needs
neither git nor graft; the exception is OUT-14e, which scans this repository live for the symbols
of the real signature change at 543477a and holds every mitigation it produces to an allowlist of
forms the test declares for itself.

`test/callsites.test.ts` holds the call-site cases. The matching is a pure function over one file's
text, so most of them need neither git nor graft; the golden case is live against this repository
and compares footprint's answer with an independent `grep` oracle, and the edges build a throwaway
git repository under `$TMPDIR` so a deleted file and a binary file are real rather than mocked.

`test/manifest.test.ts` holds the published-manifest cases (flyingrobots/footprint#35, OUT-18). Its
fixtures under `test/fixtures/npm-publish/` are captured `npm publish --dry-run --access public`
output, npm 11.20.0: one from the `v0.3.0` tree, one from the same tree with only the `bin` path
fixed. OUT-18a runs the real `npm pkg fix`, and OUT-18e and OUT-18f run the real
`scripts/manifest-check.ts`, so they need `npm` on `PATH`; the latter two also need the network,
because a publish dry run asks the registry about the package.

## Known gaps


- The structural branch is exercised with whatever graft the test machine has; no test pins
  `structural.available: true`, because graft is optional and the test must pass without it. The
  same holds for the blast radius: OUT-10a accepts either branch from the live CLI, and the
  export-surface behavior is pinned by OUT-11's fixtures instead.
- The oracle is exact for an **ASCII** symbol name. For a non-ASCII identifier footprint's
  Unicode boundary and real `grep -w` can disagree, because grep's word characters are its
  locale's and BSD grep's `-w` does not handle a multibyte pattern consistently with its own rule.
  No test asserts parity there, and the reference says so rather than implying it holds.
- The differential fuzz that found the boundary bug (2,400 random comparisons against real grep)
  was a throwaway, not a committed test: it spawns a grep per comparison and takes minutes. What
  it caught is pinned as the deterministic OUT-13f case instead.
- The call-site scan is whole-word identifier matching, so the golden case pins footprint's answer
  against `grep` and nothing else. No test distinguishes a call from a mention in a comment, a
  string or the declaration itself, because the scan cannot: that is the stated limitation, not a
  gap in the evidence. Dynamic dispatch and a re-export under another name are invisible to it and
  no test claims otherwise.
- OUT-13r and OUT-14j accept both branches of the live blast radius, graft answering or not, so
  they cannot tell on their own whether a call site was ever looked up. On CI that question is
  settled by `test/require-graft.test.ts` (flyingrobots/footprint#25), which the workflow runs
  with `FOOTPRINT_REQUIRE_GRAFT=1` and which fails unless graft answered: on this branch CI
  reported 137 pass and 1,381 `expect()` calls, against 136 pass, 1 skip and 1,379 locally, so the
  graft-dependent branches run in both places. A local run skips that guard by name, so a local
  green alone still does not prove graft answered.
- No test asserts that graft's live output still matches the fixtures. A graft release that changed
  the shape under the same `_schema` version would be caught only by OUT-10a's `counts` invariant.
- OUT-12h (graft's language module missing, or missing the exports the drift test depends on) is
  not exercised by an automated case: doing so would mean moving or breaking the real installed
  `@flyingrobots/graft`, which no fixture stands in for. The guard is in the code
  (`test/languages-drift.test.ts`'s `existsSync` and export-type checks throwing with the path
  named) and was read, not run.
- The grouping rule is the first path segment and nothing else, so no test distinguishes a
  directory that is a real subsystem from one that is not. `test/` being one system is a fact about
  this repository's layout, not a claim that its tests are one subsystem; a repository laying out
  `packages/<name>/` would get one system, `packages`, and the rule would need changing rather than
  the test. That is stated in the reference as a decision the owner may overrule, not covered by a
  case.
- No test asserts that a mitigation is *useful*, only that it is one of the three derived forms
  and that more than two of them appear on the Definition-of-Done run. Usefulness is a judgement,
  which is the thing `AGENTS.md` forbids the output from making, so there is nothing here for a
  test to assert.
- No test runs the CLI with the real `gh`. The suite keeps the real `gh` off the PATH on purpose:
  a test that listed this repository's open pull requests would depend on the network and on which
  pull requests happen to be open. Since flyingrobots/footprint#33, OUT-22a runs the CLI end to end
  with a stand-in `gh` that answers `pr list` and `pr diff --name-only` from files. That test
  asserts `overlap.available: true` and validates the result against 2.0.0. It does not cover how
  the real `gh` behaves.
- The `symbols.analysis_failed` warning, raised when the symbol-level comparison throws, has no
  automated case. Every failure that analysis expects is a coded `undetermined` result and is
  covered by OUT-22. Only an unexpected throw reaches the catch in `src/cli.ts`, and no fixture
  can produce one. The guard was read, not run.
- No case runs the symbol level on a pull request from a fork whose head was never fetched, beyond
  OUT-22i's missing commit. OUT-22i is the same code path, but a fixture has no fork.
